# V2 网站设计文档

日期：2026-06-19

## 目标

基于 `content/` 目录的 14 章章节大纲，构建网站的 v2 版本。v2 按 content/ 的结构组织页面，使用 learn 风格（因果链驱动、数字锚定、机制在先、术语在后），不影响现有 v1 页面。

## 约束

1. **不修改 v1 任何文件**——现有 `src/pages/learn/` 和 `src/pages/components/` 下的所有文件原封不动
2. **遵循 content/ 大纲**——每个 planned page 对应一个 `.mdx` 文件
3. **learn 行文规范**——因果链主导、数字锚定、机制在先术语在后、对比自带数字、无类比无营销口吻
4. **研究先行**——每章写之前先检查本地资料覆盖度，缺失的通过 WebSearch + WebFetch 下载专业资料存到 `docs/research/` 下；个人使用网站不需考虑 copyright
5. **术语规范**——中文用业内通用译法，避免英翻中/欧翻中的奇怪用词
6. **可并行则并行**——独立任务通过 parallel subagents 并行处理
7. **全量上线**——14 章全部完成后再将 v2 入口挂到首页

## URL 与文件结构

```
src/pages/v2/
  index.astro              → /v2/           （14章卡片首页）
  [chapter]/[page].mdx      → /v2/05-material-platforms/silicon-nitride/
```

v2 路由前缀 `/v2/`，不加额外 `/learn/` 层级。文件命名沿用 v1 的英文 kebab-case 惯例。

## 导航体系

- `/v2/` 首页：14 章卡片网格（复用 ChapterNav 模式，每张卡片显示 chapter title + purpose）
- 页面内：统一 `V2Layout.astro` 自动渲染面包屑 + 当前章的页面树 + 前一章/后一章翻页链接
- `/v2/` 首页不被面包屑包裹

## 基础设施

- 新建 `V2Layout.astro`：面包屑 + 章内树 + 章间翻页
- 新建 `v2Chapters.ts`：14 章每章 path 指向 `/v2/` 对应目录，含每个 planned page 的文件名和 title
- 新建 `src/pages/v2/index.astro`：14 章卡片首页
- v1 首页 `index.astro`：顶部加一条 banner 链接指向 v2 首页，不修改 v1 页面其他内容
- 现有 `content/` 目录不动——v2 不依赖它做运行时读取

## 内容迁移策略

| v1 状态 | v2 操作 | 涉及章节 |
|---------|---------|---------|
| 完整章节 | 逐页复制，调整 frontmatter 和交叉引用 | Ch.01, 03 |
| 部分完整章节 | 已有页迁移，缺失页新写 | Ch.04, 05, 06 |
| 内容丰富但错位 | 从 components/ 提取事实和数字，按 learn 风格重写因果链 | Ch.10, 11, 12 |
| 几乎空白章节 | 全部从零写，研究先行 | Ch.07, 08 |
| 只写了开头 | 补全缺失页 | Ch.00, 02, 13 |

## 实施阶段

### Phase 1：基建
- `V2Layout.astro`
- `v2Chapters.ts`
- `/v2/` 首页
- 面包屑 / 章内树 / 章间翻页组件
- v1 首页加 v2 banner

### Phase 2：迁移已有内容（~55 页）
- Ch.00（3 页）、01（5 页）、02（3 页）、03（7 页）
- Ch.05（迁 6 写 1）、06（迁 9 写 2）、09（迁 9 补 2）
- Phase 2 内各章节之间可并行

### Phase 3：从 components/ 提取重写（~35 页）
- Ch.10（16 页）、11（9 页）、12（10 页）
- 每章先从 components/ 提取事实和数字，再按 learn 风格重写因果链
- 三章之间可并行

### Phase 4：补缺失章（~23 页）
- Ch.04（补 3 缺失页）、07（全 10 页新写）、08（10 页大部分新写）
- 每章写之前先检查 docs/research/ 覆盖度，缺失资料先下载再写
- 三章之间可并行，章内独立页面也可并行

### Phase 5：收尾（~9 页）
- Ch.13（迁 4 补 5）
- 全局交叉引用检查
- 构建验证

## 页面级实施流程（每个 planned page）

1. 检查 v1 是否有对应页面 → 有则复制、调整归属、检查交叉引用
2. 检查 components/ 是否有相关内容 → 有则提取事实和数字
3. 检查 docs/research/ 是否有对应研究笔记 → 不足则 WebSearch + WebFetch 下载
4. 写页面：因果链组织 → 数字锚定 → 术语规范 → 最终落地到应用含义
5. 构建验证

## 总规模

约 120+ planned pages。其中约 40% 从 v1 迁移改写，60% 新写。
